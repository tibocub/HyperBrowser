# Documentation

How each part of HyperBrowser works, for developers. The big picture is in the [README](../README.md); how to
set up and test is in [CONTRIBUTING.md](../CONTRIBUTING.md). User documentation is the official site,
`sites/home`.

| Doc | What it covers |
|---|---|
| [engine.md](engine.md) | the engine: command line, publishing, the official apps, hosting, devices, names, notifications, circles, contacts, projects |
| [shell.md](shell.md) | the window: tabs, desktop, notifications, Configuration, circles, devices, tray, keys, icons, updates, the IDE's preview |
| [site-api.md](site-api.md) | writing a site: `site.json`, the sandbox, `window.hyper` and every call a page has |
| [forum.md](forum.md) | the forum app and the official forum |
| [chat.md](chat.md) | Contacts and Chat |
| [ide.md](ide.md) | the Hyper IDE: using it, and how it is made |
| [home-site.md](home-site.md) | the official site: building, publishing in HyperBrowser and on GitHub Pages |
| [helper.md](helper.md) | the always-on helper for a server |
| [packaging.md](packaging.md) | building, releasing, installing and updating |

`specs/` holds the design history: one folder per feature, with its spec, plan and decisions. It records how
things were decided; these docs say how they work now.
